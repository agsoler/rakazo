Chapter 03

Your daily routine

Start safely, make a focused change, verify it, and stop without data loss.

01

Orient

Check the current branch and uncommitted changes.

git status --short
02

Start the port-5300 system

Start Rakazo's development services from this source checkout, using their own Docker project, database, files, and ports. The release on port 5200 is not restarted or modified.

.\scripts\windows-dev\Start-RakazoDev.ps1
03

Work

Edit source; the development processes reload most changes.

http://127.0.0.1:5300
04

Verify

Run checks that match the risk of your change.

corepack pnpm check
05

Stop

Stop processes and containers; preserve data.

.\scripts\windows-dev\Stop-RakazoDev.ps1

What the start script actually does

Think of this script as the development environment's power button and safety checklist. It coordinates several separate programs in the correct order:

  1. Checks that the local configuration, compatible Node/pnpm, Docker Desktop, and Ollama are available.
  2. Starts or reuses PostgreSQL and the bot-computer supervisor in Docker project rakazo-dev.
  3. Installs the repository's pinned packages, applies database migrations, and builds the required sandbox images.
  4. Starts the web, API, and worker directly from this checkout, then waits for ports 5300 and 3200 to answer.

It does not erase development data, operate on Docker project rakazo, or change the published release on port 5200. If development is already healthy, running it again simply reports that it is already running.

If 5300 cannot reconnect

Start the environment again, then read the error log. Docker Desktop and Ollama must both be running.

.\scripts\windows-dev\Start-RakazoDev.ps1
Get-Content .\.local\run\source.err.log -Tail 100

Chapter 06

What survives where

A container is not a backup. An image is not your application data.

GIT

GitHub fork

Source, tracked scripts, documentation, pushed commits and branches.

Software recovery
DB

PostgreSQL volume

Users, bots, groups, messages, settings, and application records.

Not in GitHub
DIR

.local/data

Bot homes, files, revisions, and artifacts.

Not in GitHub
KEY

.env

Secrets, encryption keys, URLs, ports, and provider configuration.

Encrypted backup

Three items form a full state backup

Database dump + complete .local/data + matching .env. Store them together, encrypted, off this computer, and record the Git commit.

Chapter 07

Disaster recovery

Choose what survived. The result is determined by the evidence you still possess.

Step 1 on a rebuilt PC

Install only PowerShell 7 and Git first

They are the minimum tools needed to retrieve the fork and its machine audit. Use WinGet or the official installers.

winget install --id Microsoft.PowerShell -e --source winget
winget install --id Git.Git -e --source winget

PowerShell installerGit installer

Step 2 after cloning

Let the fork audit the machine

This read-only script checks exact Node and pnpm compatibility, Docker's Linux engine, Compose, Ollama's API, and configured models. It reports what to install; it changes nothing.

.\scripts\windows-dev\Test-RakazoDevPrerequisites.ps1

Install every item marked FAIL from its official source, then rerun the audit until no failures remain.

Official installers and version rules

Node.js

Prefer Node 24 LTS, version 24.15.0 or newer. The audit also accepts supported 22.22.2+ and 26+ releases, but not 23 or 25.

Official Node download

Docker Desktop

Install the current supported Windows release, start it, and use Linux containers. Docker Compose v2 is included.

Official Docker instructions

Ollama

Install the current Windows release and start its API on 127.0.0.1:11434. Models can be downloaded again.

Official Ollama instructions

pnpm

Do not choose a version yourself. Rakazo's scripts prepare the repository-pinned pnpm 9.15.0 beside a compatible Node installation.

What “state recovery point” means

One timestamped folder containing one consistent Rakazo moment

It contains the PostgreSQL database dump, all bot files from .local/data, the matching secret-bearing .env, the exact Git commit and tool versions, checksums, and recovery notes.

Validate first, then create it on an encrypted external drive or encrypted remote storage:

.\scripts\windows-dev\Backup-RakazoDevState.ps1 `
  -DestinationDirectory "E:\Rakazo-Backups" `
  -ValidateOnly

.\scripts\windows-dev\Backup-RakazoDevState.ps1 `
  -DestinationDirectory "E:\Rakazo-Backups"

E:\Rakazo-Backups is an example; replace it with an existing off-machine location. The backup briefly pauses only port 5300, creates a consistent snapshot, then returns development to its previous state. It contains secrets. Never commit it.

Choose a recovery scenario
RESULTWorking but empty Rakazo
  1. Install PowerShell 7 and Git using the commands or official links above.
  2. Clone the fork, add upstream, and check out integration/rakazo-dev.
  3. Run the prerequisite audit. Install each failed item and rerun it until clean.
  4. Download local Ollama models or sign in for cloud models.
  5. Run Initialize-RakazoDev.ps1 to generate new secrets.
  6. Run Start-RakazoDev.ps1, create a new account, and reconstruct bots manually.

Old users, chats, groups, bot files, and encrypted credentials are gone because Git never contained them.

RESULTSoftware and state recoverable
  1. Install PowerShell 7 and Git, then clone the fork to obtain the recovery tools.
  2. Run Test-RakazoDevRecoveryPoint.ps1. Stop if a file or checksum fails.
  3. Check out the exact Git commit printed by the verifier.
  4. Run the prerequisite audit and install every failed component.
  5. Keep Rakazo stopped. Restore the matching .env, PostgreSQL dump, and .local/data only into rakazo-dev.
  6. Start and verify the recovered baseline before updating to newer upstream code.

Restore is deliberately not one click because it replaces current data. Verify the recovery point, preserve anything newer, and use RECOVERY.txt to identify its contents and recorded code revision. The published release has separate backup and restore scripts.

The rule that saves projects

3 copies · 2 storage types · 1 off-machine

A backup on the same disk as the application does not protect against disk failure.

Chapter 08

Terms without the fog

The small vocabulary needed to reason about this setup.

origin
Our writable GitHub fork.
upstream
The official Rakazo repository we follow.
branch
A line of commits. We use one per contribution.
integration branch
The combined local experience. It is not an upstream pull request.
container
A disposable running process created from an image.
image
A packaged filesystem and recipe used to create containers.
volume
Docker-managed persistent data that survives container replacement.
bind mount
A normal Windows directory made visible inside a container.
Compose project
A named group of containers, networks, and volumes. Its name is part of our safety boundary.
migration
A versioned change to the database structure.
secret
A value that grants access or decrypts data. It never belongs in Git.
rebase
Replays commits on a newer base and rewrites their IDs. Ask before improvising.
